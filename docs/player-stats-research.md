# 昵称战绩查询调研

核对日期：2026-10-21。本文记录查询途径与接入方案，尚未添加战绩页面或上线查询服务。

## 结论

输入昵称查询公开战绩有可参考的实现。查询页面只需要昵称，背后的服务仍可能需要登录账号或站点验证。未取得用户所指的小程序名称，不能断言具体小程序采用哪一种服务。

官方的 [War Thunder Assistant 介绍](https://warthunder.com/en/community/assistant/)明确支持查看自己的统计和其他玩家的资料。社区已有助手协议客户端，可作为后续验证的线索，但不代表官方提供了面向第三方的稳定开放接口。

## 三种数据来源

### 1. 官方助手的公开资料调用

已阅读 [HSOS6/astrbot_plugin_warthunder_stats 源码](https://github.com/HSOS6/astrbot_plugin_warthunder_stats/blob/0d7b5548e8a0e9f1390452311ab870f70e0eb3d8/wt_app_client.py)，核对版本提交为 `0d7b5548e8a0e9f1390452311ab870f70e0eb3d8`。

源码使用的调用链：

1. 在服务端通过 `https://auth.gaijinent.com/login.php` 登录查询账号，获取会话。
2. 向 `https://companion-app.warthunder.com/call_signed/` 发送带认证及签名的请求。
3. `eaw_Contacts.jzx_findUsersByNickPrefix`：以昵称前缀搜索候选玩家，取得用户 ID。
4. `eaw_Profile.jzx_getPublic`：按用户 ID 读取公开资料。
5. 解码 Protobuf 响应，转换为前端需要的字段。

这里的查询账号属于服务端，并不要求每位查询者提供被查询玩家的账号密码。尚未使用任何账号完成登录和有效签名查询，数据字段和协议可用性需要后续实测。

源码还存在不宜照搬的行为：没有精确匹配时直接使用第一个候选人。产品应展示候选名单，由用户确认昵称及 ID；不能把近似昵称的战绩当作目标玩家。

### 2. 官网玩家资料页面

官网使用 `https://warthunder.com/en/community/userinfo/?nick=昵称`。官方排行榜页面也提供该类玩家链接。

[HenryXiaoYang/Warthunder-Player-API](https://github.com/HenryXiaoYang/Warthunder-Player-API/blob/HEAD/scraping.py)的实现是打开该页面、解析 HTML，再通过自身的 `/player?nick=...` 返回数据；它不是 Gaijin 官方发布的 JSON API。解析项包括基础资料、各模式战绩及累计银狮统计。

本机直接请求玩家资料页返回 403，不能作为当前已经接通的数据来源。官网排行榜和助手介绍页可以读取；不同路径的可访问性不能互相代替。

### 3. StatShark 的站内接口

[StatShark 导出工具源码](https://github.com/SwithinHalee/statshark-exporter/blob/HEAD/StatShark_Exporter_GUI.py)使用：

- `/api/stat/GetIdByName?Name=昵称&IgnoreCase=true&MaxCount=5&Details=false`
- `/api/stat/makestatrequestbyid/用户ID`

其请求携带 `X-Turnstile-Token`。这只是社区工具暴露的站内调用方式，尚未确认站点提供第三方接入授权或稳定接口承诺。本机没有验证令牌时，昵称搜索返回 406；未继续执行验证获取或批量抓取。

## 数据边界

| 数据 | 当前证据与待确认项 |
| --- | --- |
| 昵称、ID、等级、联队、称号 | 助手客户端已有字段解析，待有效会话实测 |
| 街机、历史、全真战绩 | 助手客户端已有场次、胜场、击杀及时长解析，字段口径待核对 |
| 单车战绩 | 助手客户端已有载具 ID、场次、胜场、死亡、出击、击杀等解析；各模式归属需进一步确认 |
| 各国拥有、精英载具数量 | 社区客户端提供了解码映射；属于数量统计，不能由此还原所有已购载具 ID |
| 完整已购载具清单 | 当前没有证实可仅凭昵称获取；有使用记录也不等于当前拥有，未出战载具不能据此判定未购买 |
| 收益 | 官网解析器包含累计银狮字段；不等于净收益、余额或单场到账。助手客户端未提供已验证的同类收益字段 |
| 钱包、当前研发、配件进度 | 此次没有找到可凭昵称读取的已验证方案 |
| 近期战绩 | 应记录带时间的统计快照；累计值相减只能标为区间变化，不能冒充逐场记录或固定周期官方战绩 |

## 当前请求核对

- 官方助手介绍、官方排行榜：HTTP 200。
- 官网玩家资料页：HTTP 403。
- 助手 `call_signed` 未认证、未签名请求：HTTP 400，只能证明该次请求失败，不能证明有效登录流程可用或失效。
- StatShark 无验证令牌的昵称搜索：HTTP 406。
- 没有调用账号登录，没有关闭二次验证，没有读取本机游戏凭据，也未绕过验证。

## 建议的项目接入方式

采用“页面输入昵称 → 自有查询服务 → 候选玩家 → ID 对应公开战绩”的流程。前端继续静态发布；查询会话、签名私钥等仅留在服务端。部署位置可以单独选择 NAS 服务或其他可信服务端；尚未选择 QMuse 云服务。

建议先做小范围验证：手动登录官方助手核对样本玩家，再验证允许使用的服务端认证方式与公开资料请求。验证失败就保留研究结论，不在界面展示虚构数据，也不要求用户关闭二次验证。

通过后再实现独立战绩页面：候选玩家确认、模式切换、总览、单车排行、来源和更新时间。按用户 ID 缓存，合并相同查询，设置访问间隔、超时与退避，遇验证码或限流暂停；可用时展示带时间的旧数据。未知字段保持空值，未知 K/D 或零死亡不伪装成 0。

已有研究计算、浏览器方案、购物车和队列记录保持独立。公开单车战绩不会自动写入“已有载具”；完整拥有清单必须另行核实并由用户确认。

原始网页、源码和请求记录保存在未发布的 `artifacts/stats-research/`，不进入应用包。
