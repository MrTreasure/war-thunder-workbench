# 昵称战绩查询调研

核对日期：2026-10-21。本文记录查询途径与接入验证结果，查询功能尚未对外上线。

## 结论

已通过用户授权的查询账号连接官方助手服务，完成邮箱验证、昵称搜索及两名玩家的公开资料读取。查询者可以只输入昵称，后端查询账号需要有效登录会话。未取得用户所指的小程序名称，不能断言具体小程序采用哪一种服务。

官方的 [War Thunder Assistant 介绍](https://warthunder.com/en/community/assistant/)明确支持查看自己的统计和其他玩家的资料。社区已有助手协议客户端，可作为后续验证的线索，但不代表官方提供了面向第三方的稳定开放接口。

## 三种数据来源

### 1. 官方助手的公开资料调用

已阅读 [HSOS6/astrbot_plugin_warthunder_stats 源码](https://github.com/HSOS6/astrbot_plugin_warthunder_stats/blob/0d7b5548e8a0e9f1390452311ab870f70e0eb3d8/wt_app_client.py)，核对版本提交为 `0d7b5548e8a0e9f1390452311ab870f70e0eb3d8`。

源码使用的调用链：

1. 在服务端通过 `https://auth.gaijinent.com/login.php` 登录查询账号，获取会话。
2. 向 `https://companion-app.warthunder.com/call_signed/` 发送带认证及签名的请求。
3. `eaw_Contacts.jzx_findUsersByNickPrefix`：以昵称前缀搜索候选玩家，取得用户 ID。
4. `eaw_Profile.jzx_getPublic`：按用户 ID 读取公开资料。
5. 解码 Protobuf 响应，转换为前端需要的字段。

这里的查询账号属于服务端，并不要求每位查询者提供被查询玩家的账号密码。2026-10-21 已通过邮箱验证，并在同一会话内成功完成昵称搜索及公开资料查询，得到可解析的真实响应。字段是否存在已经核对；部分名称与统计口径仍须与游戏界面比对，不能由未命名数值推断收益或所有权。

源码还存在不宜照搬的行为：没有精确匹配时直接使用第一个候选人。产品应展示候选名单，由用户确认昵称及 ID；不能把近似昵称的战绩当作目标玩家。实测同一搜索结果同时出现大小写不同、ID 不同的昵称，不得忽略大小写后直接取第一个。

### 2. 官网玩家资料页面

官网使用 `https://warthunder.com/en/community/userinfo/?nick=昵称`。官方排行榜页面也提供该类玩家链接。

[HenryXiaoYang/Warthunder-Player-API](https://github.com/HenryXiaoYang/Warthunder-Player-API/blob/HEAD/scraping.py)的实现是打开该页面、解析 HTML，再通过自身的 `/player?nick=...` 返回数据；它不是 Gaijin 官方发布的 JSON API。解析项包括基础资料、各模式战绩及累计银狮统计。

本机直接请求玩家资料页返回 403，不能作为当前已经接通的数据来源。官网排行榜和助手介绍页可以读取；不同路径的可访问性不能互相代替。

### 3. StatShark 的站内接口

[StatShark 导出工具源码](https://github.com/SwithinHalee/statshark-exporter/blob/HEAD/StatShark_Exporter_GUI.py)使用：

- `/api/stat/GetIdByName?Name=昵称&IgnoreCase=true&MaxCount=5&Details=false`
- `/api/stat/makestatrequestbyid/用户ID`

其请求携带 `X-Turnstile-Token`。这只是社区工具暴露的站内调用方式，尚未确认站点提供第三方接入授权或稳定接口承诺。本机没有验证令牌时，昵称搜索返回 406；未继续执行验证获取或批量抓取。

## 数据边界

按功能整理的完整清单见[战绩查询可用数据](player-stats-data-catalog.md)。

| 数据 | 当前证据与待确认项 |
| --- | --- |

| 街机、历史、全真战绩 | 响应包含模式分组、场次、胜场、击杀和时长相关字段；第二个样本包含全真记录。模式及字段名称参考社区映射，仍需游戏界面确认口径 |
| 单车战绩 | 已取得载具 ID、模式分组、场次、胜场、死亡、出击、空中/地面/海上击杀等字段；部分记录只有载具 ID 或少数字段，缺项保持未知 |
| 各国拥有、精英载具数量 | 响应已取得各国计数字段，名称依据社区映射；缺省国家或精英计数不补零。这些总数不能还原完整已购载具 ID |
| 完整已购载具清单 | 本次公开资料响应不能证明可以获取。单车记录不等于完整拥有清单，不能自动同步为科技树中的已购载具 |
| 收益 | 单车响应字段 10 已取得数值，参考客户端称为“战争点数”。游戏统计脚本存在 `wp_total` 的获得货币栏目，本地化说明不含嘉奖和任务成就；助手字段 10 是否确切对应此栏目，仍待游戏数值对照。不能标为余额、净收益或逐场到账 |
| 钱包、当前研发、配件进度、注册日期 | 此次公开资料响应没有取得经过确认的字段，不展示推测值 |
| 近期战绩 | 响应含多个排行榜字段与排名，部分值为 `-2` 等无数据标志；近期时间窗口尚未确认。自行保存累计快照只能展示区间变化，不能冒充逐场记录 |

## 收益字段补充核对

参考插件有两条不同分支：

- 默认 `data_source=app`：官方登录、签名昵称搜索、公开资料查询及 Protobuf 解码。`wt_app_client.py` 将单车字段 10 标为“战争点数”，字段 9 标为“在线经验”，并没有在助手分支中给出已核实的 `Lions earned` 统一口径。
- `data_source=official`：读取官网玩家资料 HTML，再通过 `main.py` 的解析与格式化代码显示 `Lions earned`。本机该页面此前返回 403，未接通这条收益来源。源码能格式化该列，不等于当前助手返回已经验证了该列。

另已阅读游戏文件中的 [userInfoStats.nut](https://github.com/gszabi99/War-Thunder-Datamine/blob/ea96f3af75afe1d858f80ac13f212db218bc69ca/gui.vromfs.bin_u/scripts/user/userinfostats.nut)：单车统计配置含 `wp_total`，使用 `multiplayer/wp_total_gained` 标签，且标记 `ownProfileOnly=true`。对应 [游戏本地化](https://github.com/gszabi99/War-Thunder-Datamine/blob/ea96f3af75afe1d858f80ac13f212db218bc69ca/lang.vromfs.bin_u/lang/menu_multiplayer.csv)的中文说明为已获得货币，不含嘉奖和任务成就；与任务得分 `multiplayer/score` 是不同栏目。

因此助手单车字段 10 可能对应累计银狮，但目前只是结合字段映射和游戏统计代码得到的推断。已向用户提供两个本人载具的实际返回数值。用户暂不方便进入游戏对照，认为数据应当正确；记录为“累计银狮候选字段，口径待游戏核对”，不提升为已完成游戏核对。未核对前不把它发布为银狮收益，也不由此推断余额或净利润。

## 当前请求核对

- 官方助手介绍、官方排行榜：HTTP 200。
- 官网玩家资料页：HTTP 403。
- 助手 `call_signed` 未认证、未签名请求：HTTP 400，只能证明该次请求失败，不能证明有效登录流程可用或失效。
- StatShark 无验证令牌的昵称搜索：HTTP 406。
- 用户授权后，邮箱验证码登录返回 `OK` 并取得会话；有效签名的昵称搜索与两名玩家公开资料查询均成功返回 HTTP 200。未关闭或绕过二次验证。

## 账号验证进度（2026-10-21）

1. 北京时间 17:09 首次登录收到 HTTP 200 JSON，要求二次验证，未取得会话。
2. 通过用户提供的邮箱验证码，于 17:17 取得有效会话；带签名的昵称前缀搜索成功返回 HTTP 200，并解码出用户 ID、昵称和头像标识。
3. 搜索 `MrTreasure` 仅返回近似昵称 `MrTreasurehead@psn`，不是精确匹配，因此没有读取或冒充目标账号的资料。
4. 研究进程在搜索后结束，未保留会话。用户随后指定目标游戏昵称 `ArthurDaynee`；再次登录未通过邮箱验证，当时需等待新的验证码，后续已在同一进程内完成资料核对。
5. 17:25 用户反馈没有收到新邮件后，重新提交一次不带旧验证码的登录。官方返回 `2STEP`，并明确 `hasTwoStepEmail=true`、`hasGjPass=false`、`hasWTR=false`，没有 `requestId`。保留同一个 HTTP 客户端、设备标识和签名密钥等待验证码，未自动重复发送。该返回本身只确认验证方式，不能称作已确认发信成功。用户随后明确确认收到邮件。
6. 17:27 提交用户新提供的验证码，官方返回 `OK` 并取得会话。精确匹配目标昵称，成功读取公开资料，解码出基础资料、等级、各国计数、13 个统计分组与单车记录。
7. 在同一个会话内搜索另一名公开玩家，按明确的昵称和 ID 读取其资料也成功，验证了查询其他玩家公开资料无需对方账号密码。原始响应只留在被忽略的研究目录，不随应用或文档发布。

当前已验证**邮箱验证登录、带签名昵称搜索及公开资料查询可行**。公开资料包含基础信息、统计与单车数据；收益含义、完整已购清单、当前研发等仍未验证。不能把“收到该字段”和“字段含义已由游戏界面确认”混为一谈。

邮箱验证码字段依据 [Gaijin 官方开源登录实现](https://github.com/GaijinEntertainment/DagorEngine/blob/2baf19472d60b96b437b2f9e549a3a6c8958cfd8/prog/1stPartyLibs/yuplay2auth/session/yu_sessionLogin.cpp)核对，为 `2step`。未关闭或绕过二次验证。验证码、密码、登录响应正文、会话与签名私钥不写入文件或日志；私有研究记录仅保存时间、结果类别和公开查询返回。

## 建议的项目接入方式

完整的双能力方案、Top 5、原生素材、AI 与效率值规则见[战绩查询与 AI 战报方案](player-stats-report-plan.md)。

采用“页面输入昵称 → 自有查询服务 → 候选玩家 → ID 对应公开战绩”的流程。前端继续静态发布；查询会话、签名私钥等仅留在服务端。按用户已明确的结构：独立小服务负责查询，admin-console 负责会话与后台管理，战雷科技树应用提供查询入口，接口通过现有 Cloudflare 对外。页面开发暂缓，先完成实际数据边界核对。

小范围连接验证已完成。下一步应将样本统计与游戏界面核对，确认缺省字段、无数据标志与指标口径，再确定页面展示范围；不要求用户关闭二次验证。

通过后再实现独立战绩页面：候选玩家确认、模式切换、总览、单车排行、来源和更新时间。按用户 ID 缓存，合并相同查询，设置访问间隔、超时与退避，遇验证码或限流暂停；可用时展示带时间的旧数据。未知字段保持空值，未知 K/D 或零死亡不伪装成 0。

已有研究计算、浏览器方案、购物车和队列记录保持独立。公开单车战绩不会自动写入“已有载具”；完整拥有清单必须另行核实并由用户确认。

原始网页、源码和请求记录保存在未发布的 `artifacts/stats-research/`，不进入应用包。
