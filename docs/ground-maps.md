# 陆战地图

## 地图 API 加载（2026-10-29）

本轮独立预览通过数据库版本化 API 加载公开地图清单，运行时不再依赖打包的整份地图 JSON。超管走线通过鉴权请求获取索引与 SVG，校验哈希后使用内存 Blob URL，PNG 导出复用同一图层。地图缓存独立于国家资料和用户 OPFS 方案；切换身份立即移除走线。


预览入口：<https://render.mrtreasure.cc/muse/war-thunder-trees/#/maps>。
顶部导航和手机页面切换菜单直接展示“陆战地图”，无需额外参数。旧的 `?guides=1` 入口仍可使用。

## 资料和功能

2026-10-21 用户提供两份导出资料，收录 55 张陆战底图、77 张三点占领点位缩略图、309 个任务布局和 2242 个简报点位。列表可按中文、英文和关联攻略搜索；详情可切换任务布局、己方队伍、等高线、点位、布局裁切与参考网格，支持拖动、缩放和复位。地图区域可通过方向键平移、Home 复位。

列表使用 DOM 包的 77 个布局对应关系与原生标记；原包的合成图也有上下反向问题，因此按修正后的坐标在原底图上重建预览，最长边 512 像素，不翻转地形或字母。详情保留原始无损 WebP，不从缩略图放大。底图、等高线与点位在修正方向后共用 0–1000 坐标，布局裁切只限制地图层范围，不改变图层的相对位置，也不裁切自定义画布标注。等高距 5 米，主等高距 25 米；高度是世界 Y 坐标，不能当作已校准海拔。等高线不包含建筑、桥梁或碰撞/通行性信息。网格来自地图文件参考参数，未与具体对局校准。点位为简报参考位置。

关联攻略保留原始作者链接和年份，仅提示同地图相关资料，不声称旧版攻略与当前任务布局完全一致。冬季地图不会自动继承普通季节攻略。旧攻略数据仍在 `data/map-atlas.json`、`data/map-collections.json`，没有删除或覆盖，也没有继续触发外部采集。

## 图片托管

使用已有图床仓库 [MrTreasure/oss-files](https://github.com/MrTreasure/oss-files)，目录为 `war-thunder/ground-maps/v1/`。193 个图片对象与源码分仓保存：55 张底图、55 个等高线 SVG、77 张缩略图和 6 个点位图标。URL 固定到完整 Git 提交 ID，文件名带内容哈希，避免分支更新改变旧版页面。

图片首先通过 jsDelivr 访问仓库固定版本的文件，失败时尝试 GitHub 原始文件；底图、等高线与图标还保留已存在的 R2 备份。修正后的缩略图不回退到原包中方向错误的合成图。R2 原图未删除。`oss.mrtreasure.cc` 的旧测试文件当前返回 404，尚未把这个未经核验的域名用于新图片，也未修改其全站绑定。

底图维持原始 WebP；等高线 SVG 仅压缩数字书写和省略重复的直线命令，逐项验证所有数值坐标未改变。归档共约 338.8 MiB，最大单文件 19,748,407 字节。大体积图片、原始 ZIP 与巨大等高线坐标 JSON 不进入应用源码仓库或 QMuse 上传。

原先选择 R2 是为了控制源码仓库大小；GitHub 图片仓库同样可行，本次按已有图床仓库接入。元数据中的 `sourceSha256` 保留原文件哈希，`sha256` 对应仓库文件，`fallbackSha256` 对应 R2 备份。

## 重新准备

在独立 Python 环境安装 Pillow 13.0.0、CairoSVG 2.9.1；R2 上传额外需要 boto3 1.43.115、PyYAML 6.0.3。先准备本机导出文件，再归档到图床仓库：

```sh
python scripts/prepare-ground-maps.py '<解压后的战雷陆战地图目录>' '<解压后的缩略图目录>'
# prepare 会自动修正方向、重建缩略图；已有目录可单独运行以下命令：
python scripts/correct-ground-map-projection.py --maps '<地图目录>' --thumbs '<缩略图目录>'
python scripts/audit-ground-map-projection.py --source '<地图目录>'
python scripts/archive-ground-map-assets.py --repo '<oss-files 本地工作目录>' --source '<解压后的战雷陆战地图目录>'
# 审查并提交、推送 oss-files 中 war-thunder/ground-maps/ 的新增文件。
python scripts/archive-ground-map-assets.py --repo '<oss-files 本地工作目录>' --source '<解压后的战雷陆战地图目录>' --apply-ref '<图床仓库完整提交ID>'
```

归档脚本不读取密钥、不推送。原 R2 上传脚本仅在显式追加 `--upload` 时读取密码本 `cloudflare.r2_admin`。资产提交确认上传后再固定版本链接并构建，禁止发布尚未推送的图片版本。

规范数据在 `data/ground-maps.json`，仅由地图页面的懒加载 JS 携带。常规 `pnpm run check` 检查地图数量、任务布局、坐标投影、缩略图关联、资源哈希和图床版本；`pnpm run build` 保持原有国家数据与禁止独立 JSON 的检查。预览仍通过 `pnpm run publish`，QMuse 等待用户确认。

## 自定义走线编辑

地图详情点击“编辑走线”进入沉浸式编辑，应用顶部导航收起。左侧只保留选择、平移、战术线、画笔、形状、标记、文字七项。战术线及属性面板使用可收起的浮层，展开、关闭和切换均不改变画布尺寸或地图位置；移动端浮层位于底部工具栏上方。

- **选择 / 平移**：选择标注拖动；平移工具拖动地图。选中对象后可用方向键微调，Shift 加速。
- **箭头 / 线条**：拖出起点和终点，松手即完成并选中；也支持依次点击起点、终点。拖动实心端点调整线条，拖动空心中点添加拐点，双击拐点删除。无需再到另一处确认完成。
- **曲线**：在“战术线”浮层中切换“平滑曲线”，拖出一条带弧度的路线，松手后拖动端点和中间点调整；现有线条可在属性中切换“平滑曲线”，曲线也可带箭头和战术线样式。
- **军事战术线**：左侧“战术线”打开带实际线型预览的列表：绿色折齿防御阵线、弧齿前沿线、中空宽箭头进攻轴线、开口箭头进攻方向、虚线撤退路线、三角齿反坦克壕线、交叉障碍线、补给线和射界线。在浮层中选择“绿色防御阵线”即可绘制；阵线可翻转朝向，仍支持改色和曲线。预设与查阅来源保存在 `data/map-editor-lines.json`。
- **形状**：矩形、椭圆和可编辑多边形，拖动创建范围，控制点调整大小；多边形支持在边中点拖出新顶点。
- **危险区**：“形状”中选择“危险区域（多边形）”，拖出带半透明填充、斜线和“危险区域”说明的多边形，可修改轮廓、颜色、透明度与说明。
- **战术符号**：左侧“标记”默认打开“战术符号”，提供狙击点、观察点、伏击点、防御阵地、反坦克阵地、火力支援、集结点、补给点、维修点、救援点、防空警戒、雷区标记、危险点、途经点，共 14 种。支持搜索、改色、缩放、旋转和说明文字；这些是项目绘制的攻略示意符号，与游戏原生图标分开展示。
- **狙击点**：“标记 → 战术符号 → 狙击点”可放置瞄准十字与“狙击点”说明，旧草稿中使用原生图标的狙击点继续保留。
- **端点编辑**：属性区可选择起点、终点或拐点，输入 X/Y 百分比，或用方向键微调，Shift 加速。可添加或删除拐点；一次拖动对应一步撤销。
- **颜色**：提供友军绿、敌军红、蓝色、标记黄、浅灰、金色，也支持自选颜色。选中标注后改色即时生效，新标注沿用最近选用的颜色。预设及来源说明见 `data/map-editor-palette.json`。
- **画笔**：按住拖动，松开完成。单条走线最多 3000 点。
- **战雷原生图标**：“标记 → 战雷原生”保留 79 个游戏 SVG，点击地图放置；可调整大小、旋转、颜色底圈和文字说明。玩家坦克图标的原始资源缺少 SVG 命名空间，现使用仅补齐根节点命名空间和 viewBox 的兼容版本，保留原文件和原始 SHA，图形与颜色不变。
- **文字**：点击地图放置文字，支持换行、字号、颜色及旋转。
- **图层 / 一键清除**：选择、隐藏、锁定、调整顺序、复制或删除标注。主工具栏“清除标记”一键清除当前地图、布局和队伍的全部自定义标注，包括隐藏和锁定项；可直接撤销恢复。任务原生点位由底图图层开关控制。

地图是画布上的独立图层，按比例显示并保留绘图留白。只有地图、等高线和原生任务点位使用地图层裁切框，自定义线条、区域、符号和文字在独立画布层绘制，可跨越地图边缘并延伸到地图外。平移操作移动整张画布视窗，允许查看地图外区域；主工具栏独立占位，辅助面板悬浮于画布上方；面板开关不改变地图的显示范围。PNG 导出使用同一画布视窗，包含当前留白及其中的自定义标注。

标注坐标仍相对于完整底图，不随显示裁切、缩放或平移改变；允许负坐标及大于 1 的坐标来表示地图外位置，旧的 0–1 坐标草稿继续兼容。原有任务点位与等高线是独立只读图层。每张地图、每个任务布局和己方队伍分别保存本地草稿，最多 500 个标注、累计 50000 个走线点；撤销历史保留 60 步。浏览器存储被拒绝或空间不足时明确提示，可导出编辑文件保留结果，不会清理其它用户数据。

顶部“导出”打开文件面板，可导出 `.wtmap.json`，通过“导入编辑文件”继续编辑，也可发送给其他人使用。导入前校验版本、地图、布局、队伍、图标 ID、坐标、颜色和内容大小，并确认替换目标草稿；允许自动打开文件对应的地图与队伍。导入数据不能指定任意外部图片或执行内容。文件上限 4 MiB。

“导出图片”将当前地图视窗中的底图、可见等高线、网格、任务点位和自定义标注合成为 2K 或 4K PNG，隐藏标注及编辑控件不进入图片。图层图片通过允许跨域使用的 Image 加载后绘入 Canvas；遇到跨域拒绝或网络失败会尝试备用源并明确提示，导出过程中可以取消。PNG 是预览视窗的分享图片，编辑文件保留全部标注及完整地图坐标。

原生图标归档版本：`afd8e14f043cec070122fc1f600ba3932f4dded3`。原文件仍保留在原哈希路径，玩家坦克的兼容版本另存于新哈希路径，来源与修正记录在 `data/map-editor-icons.json`。准备脚本为 `scripts/prepare-map-editor-icons.py`。战术符号保存在 `data/map-editor-symbols.json`，SVG 显示与 PNG 导出共用相同图形定义，编辑文件仅引用允许的标记 ID。它们随地图页面懒加载 JS 发布。

导入确认弹窗按内容收缩、居中展示，内容过长时内部滚动；一键清除不再弹出确认框，可用撤销恢复。

验证：`pnpm run check:map-editor` 覆盖编辑文件往返、恶意与异常输入拒绝、移动边界、箭头端点、撤销/重做与合并历史、草稿隔离及存储失败。此项已经加入 `pnpm run check`。交互与实际 PNG 效果按项目规则由浏览器验收。

### 线条交互参考

- [Excalidraw 线条编辑](https://github.com/excalidraw/excalidraw/blob/master/packages/element/src/linearElementEditor.ts)：端点编辑与拖动线段中点增加拐点；使用拖动阈值，避免普通点击意外增加拐点。

已存在的走线文件及本地草稿保持版本 1；曲线和战术线使用可选字段扩展，区域增加 `shape` 类型。当前版本可以继续导入旧文件并修改端点与拐点；新增文件需要支持这些形状的版本打开。

### 军事线型参考

已查阅 [Mission Command mil-sym-ts](https://github.com/missioncommand/mil-sym-ts) 的多点战术图形实现，以及 [milsymbol](https://github.com/spatialillusions/milsymbol) 的单位符号说明。二者分别覆盖多点线面图形与单位点符号，不把基地字母图标当作全部战术元素。

- [TacticalLines](https://github.com/missioncommand/mil-sym-ts/blob/development/src/main/ts/armyc2/c5isr/JavaLineArray/TacticalLines.ts) 区分 FORTL 工事线、FLOT 前沿线、ATDITCH 反坦克壕线、DIRATKGND 进攻方向与撤退图形。
- [flot 的前沿线绘制](https://github.com/missioncommand/mil-sym-ts/blob/development/src/main/ts/armyc2/c5isr/JavaLineArray/flot.ts) 提供弧齿图形的参考，与折齿工事线区分。
- [arraysupport 的 FORTL 绘制](https://github.com/missioncommand/mil-sym-ts/blob/development/src/main/ts/armyc2/c5isr/JavaLineArray/arraysupport.ts) 使用折齿结构；本项目据其图形语义独立绘制，不再用三角齿统称防御线。
- 默认绿色来自用户指定的战雷攻略配色，可修改；不把绿色声明成某一军标的统一要求。这里只提供攻略绘图所需的线型子集，不宣称整套军标认证。

SVG 画布、线型预览和 PNG 导出使用同一几何生成函数，包含线条端部、朝向翻转与曲线上的连续符号间距。

中空进攻轴线的折点先生成圆弧过渡，再沿连续切线生成两侧轮廓，保持常规转弯处的宽度，避免内侧折返和外侧突跳。已有箭头保留原来的编辑点和存储格式，重新显示及导出时使用修正后的轮廓。

## 多方案与文字字体

“编辑走线”顶部新增“方案”入口，按地图、任务布局与己方队伍分别管理多套方案。支持新建空白方案、另存为、重命名、切换和删除，修改自动写入专用 OPFS 目录 `wt-map-plans-v1`。原有 `wt-map-editor-v1:*` 草稿会在首次迁移时恢复到默认方案，旧记录保留；新方案不写入 localStorage，也不属于可清理的数据缓存。

文字标注新增系统黑体、宋体/衬线、楷体、等宽和战术窄体选择，以及字重与斜体。字体依设备可用性回退，SVG 与 PNG 共用受控字体清单，导出前等待所需字体。旧编辑文件没有字体设置时保持原有默认样式；导入不接受任意字体地址或 CSS。

## 点位与等高线方向修正（2026-10-21）

用户提供的柏林与美国沙漠实战对照确认：地图纹理保持原方向，世界 Z 增加对应图片向上。此前把世界 Z 增加当作图片向下，导致点位及等高线整体上下相反。原始 DOM 合成图使用同一套旧投影，因此两份导出资料彼此吻合不能证明与游戏吻合。

修正后 `u=(worldX-minX)/(maxX-minX)`，`v=(maxZ-worldZ)/(maxZ-minZ)`。2242 个标记保留原始世界坐标；309 个任务布局的裁切框按 `[u0,1-v1,u1,1-v0]` 修正。参考网格以纹理左上角对应的世界位置为原点，字母向下排列，世界 Z 递减。网格仍不是已校准的具体对局网格。

55 份等高线原始数据及固定版本图源保持不变；SVG 图层与 PNG 导出共用 `matrix(1 0 0 -1 0 1000)`，只对等高线图片进行一次纵向反射。不会反射底图、图标中的字母或用户绘制内容。

77 张列表缩略图沿用 DOM 包的地图、布局 ID 和原始哈希，在原底图上重新投影原生点位，最长边 512 像素，合计约 4.39 MiB。原始 DOM 哈希保存在缩略图的 `sourceSha256`，修正后的图片哈希在 `image.sha256`。新图通过 Git 图床固定提交 `db1259348b7c0168a0606b1463553a8bc56b0ccf` 发布，备用源为同一图片的 GitHub 原始地址，避免回退到旧错误点位图。

“来自游戏文件”指底图纹理和任务简报坐标的来源。DOM 包说明明确表示，点位图经过坐标投影后合成，并非游戏直接渲染的地图截图；导出过程用错投影方向仍会把正确的源数据合成为错误位置。原始 DOM 文件保留作为来源依据，不再用两份同源导出互相证明方向正确。

核对覆盖全部 55 张地图、309 个任务布局、2242 个点位和 59392 条等高线的起点。原始等高线坐标与其 SVG 起点在一次反射后吻合，最大误差为 SVG 四位小数舍入量（约 0.00005/1000）；这证明了投影一致性，不代替建筑、桥面或实战通行性的核实。核对脚本为 `scripts/audit-ground-map-projection.py`，完整记录保存在忽略目录 `artifacts/ground-maps/point-audit/projection-report.json`。

## 推荐走线（2026-10-26）
