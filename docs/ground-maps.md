# 陆战地图

预览入口：<https://render.mrtreasure.cc/muse/war-thunder-trees/?guides=1#/maps>。
默认页面不显示入口，只有外层查询字符串 `guides=1` 才启用陆战地图导航与路由。

## 资料和功能

2026-10-21 用户提供两份导出资料，收录 55 张陆战底图、77 张三点占领点位缩略图、309 个任务布局和 2242 个简报点位。列表可按中文、英文和关联攻略搜索；详情可切换任务布局、己方队伍、等高线、点位、布局裁切与参考网格，支持拖动、缩放和复位。地图区域可通过方向键平移、Home 复位。

缩略图由 DOM 点位图缩小至最长边 512 像素。详情保留原始无损 WebP，不从缩略图放大。底图、等高线与点位共用 0–1000 坐标，裁切只调整视窗，不改变各图层的相对位置。等高距 5 米，主等高距 25 米；高度是世界 Y 坐标，不能当作已校准海拔。等高线不包含建筑、桥梁或碰撞/通行性信息。网格来自地图文件参考参数，未与具体对局校准。点位为简报参考位置。

关联攻略保留原始作者链接和年份，仅提示同地图相关资料，不声称旧版攻略与当前任务布局完全一致。冬季地图不会自动继承普通季节攻略。旧攻略数据仍在 `data/map-atlas.json`、`data/map-collections.json`，没有删除或覆盖，也没有继续触发外部采集。

## 图片托管

使用已有图床仓库 [MrTreasure/oss-files](https://github.com/MrTreasure/oss-files)，目录为 `war-thunder/ground-maps/v1/`。193 个图片对象与源码分仓保存：55 张底图、55 个等高线 SVG、77 张缩略图和 6 个点位图标。URL 固定到完整 Git 提交 ID，文件名带内容哈希，避免分支更新改变旧版页面。

图片首先通过 jsDelivr 访问仓库固定版本的文件，失败时依次尝试 GitHub 原始文件和已存在的 R2 备份。R2 原图未删除。`oss.mrtreasure.cc` 的旧测试文件当前返回 404，尚未把这个未经核验的域名用于新图片，也未修改其全站绑定。

底图维持原始 WebP；等高线 SVG 仅压缩数字书写和省略重复的直线命令，逐项验证所有数值坐标未改变。归档共约 338.8 MiB，最大单文件 19,748,407 字节。大体积图片、原始 ZIP 与巨大等高线坐标 JSON 不进入应用源码仓库或 QMuse 上传。

原先选择 R2 是为了控制源码仓库大小；GitHub 图片仓库同样可行，本次按已有图床仓库接入。元数据中的 `sourceSha256` 保留原文件哈希，`sha256` 对应仓库文件，`fallbackSha256` 对应 R2 备份。

## 独立详情页

点击卡片打开 `#/maps/地图ID?side=布局ID`。详情页与列表共用顶部导航，支持直接访问、刷新、前进/后退和返回列表；列表搜索与仅看有关联攻略的筛选保存在路由中。旧 `#/maps?map=...&side=...` 链接自动跳转。未知地图提供返回列表入口，没有外层 `guides=1` 时依旧返回科技树。

## 重新准备

在独立 Python 环境安装 Pillow 13.0.0；R2 上传额外需要 boto3 1.43.115、PyYAML 6.0.3。先准备本机导出文件，再归档到图床仓库：

```sh
python scripts/prepare-ground-maps.py '<解压后的战雷陆战地图目录>' '<解压后的缩略图目录>'
python scripts/archive-ground-map-assets.py --repo '<oss-files 本地工作目录>' --source '<解压后的战雷陆战地图目录>'
# 审查并提交、推送 oss-files 中 war-thunder/ground-maps/ 的新增文件。
python scripts/archive-ground-map-assets.py --repo '<oss-files 本地工作目录>' --source '<解压后的战雷陆战地图目录>' --apply-ref '<图床仓库完整提交ID>'
```

归档脚本不读取密钥、不推送。原 R2 上传脚本仅在显式追加 `--upload` 时读取密码本 `cloudflare.r2_admin`。资产提交确认上传后再固定版本链接并构建，禁止发布尚未推送的图片版本。

规范数据在 `data/ground-maps.json`，仅由隐藏地图页面的懒加载 JS 携带。常规 `pnpm run check` 检查地图数量、任务布局、坐标投影、缩略图关联、资源哈希和图床版本；`pnpm run build` 保持原有国家数据与禁止独立 JSON 的检查。预览仍通过 `pnpm run publish`，QMuse 等待用户确认。

## 自定义走线编辑

地图详情点击“编辑走线”进入沉浸式编辑，应用顶部导航收起。工具与属性区占用画布外的独立空间；移动端工具栏和可收起的属性区在画布下方。

- **选择 / 平移**：选择标注拖动；平移工具拖动地图。选中对象后可用方向键微调，Shift 加速。
- **箭头 / 线条**：拖出起点和终点，松手即完成并选中；也支持依次点击起点、终点。拖动实心端点调整线条，拖动空心中点添加拐点，双击拐点删除。无需再到另一处确认完成。
- **曲线**：拖出一条带弧度的路线，松手后拖动端点和中间点调整；现有线条可在属性中切换“平滑曲线”，曲线也可带箭头和战术线样式。
- **战术示意线**：提供普通路线、进攻方向、撤退路线、补给路线、观察 / 射界线、防御阵线、障碍 / 封锁线。可调整实线、虚线、点线、点划线、锯齿或交叉记号；这些是攻略示意，不宣称遵循特定军标。预设保存在 `data/map-editor-lines.json`。
- **形状**：矩形、椭圆和可编辑多边形，拖动创建范围，控制点调整大小；多边形支持在边中点拖出新顶点。
- **危险区**：直接拖出带半透明填充、斜线和“危险区域”说明的多边形，可修改轮廓、颜色、透明度与说明。
- **战术符号**：左侧“标记”默认打开“战术符号”，提供狙击点、观察点、伏击点、防御阵地、反坦克阵地、火力支援、集结点、补给点、维修点、救援点、防空警戒、雷区标记、危险点、途经点，共 14 种。支持搜索、改色、缩放、旋转和说明文字；这些是项目绘制的攻略示意符号，与游戏原生图标分开展示。
- **狙击点**：也可通过左侧快捷工具直接放置瞄准十字与“狙击点”说明，旧草稿中使用原生图标的狙击点继续保留。
- **端点编辑**：属性区可选择起点、终点或拐点，输入 X/Y 百分比，或用方向键微调，Shift 加速。可添加或删除拐点；一次拖动对应一步撤销。
- **颜色**：提供友军绿、敌军红、蓝色、标记黄、浅灰、金色，也支持自选颜色。选中标注后改色即时生效，新标注沿用最近选用的颜色。预设及来源说明见 `data/map-editor-palette.json`。
- **画笔**：按住拖动，松开完成。单条走线最多 3000 点。
- **战雷原生图标**：“标记 → 战雷原生”保留 79 个游戏 SVG，点击地图放置；可调整大小、旋转、颜色底圈和文字说明。玩家坦克图标的原始资源缺少 SVG 命名空间，现使用仅补齐根节点命名空间和 viewBox 的兼容版本，保留原文件和原始 SHA，图形与颜色不变。
- **文字**：点击地图放置文字，支持换行、字号、颜色及旋转。
- **图层**：选择、隐藏、锁定、调整顺序、复制或删除标注；清空需要确认，随后仍可撤销。

地图按所选布局的原始比例居中显示，允许四周留白，不为铺满画布而扩大或裁切地图。平移被限制在底图边界内。底图与标注共用同一范围，工具及属性区独立占位；导出图片使用相同视窗，不包含画布留白。

标注坐标采用完整底图的归一化 UV，不随显示裁切、缩放或平移改变。原有任务点位与等高线是独立只读图层。每张地图、每个任务布局和己方队伍分别保存本地草稿，最多 500 个标注、累计 50000 个走线点；撤销历史保留 60 步。浏览器存储被拒绝或空间不足时明确提示，可导出编辑文件保留结果，不会清理其它用户数据。

顶部“导出”打开文件面板，可导出 `.wtmap.json`，通过“导入编辑文件”继续编辑，也可发送给其他人使用。导入前校验版本、地图、布局、队伍、图标 ID、坐标、颜色和内容大小，并确认替换目标草稿；允许自动打开文件对应的地图与队伍。导入数据不能指定任意外部图片或执行内容。文件上限 4 MiB。

“导出图片”将当前地图视窗中的底图、可见等高线、网格、任务点位和自定义标注合成为 2K 或 4K PNG，隐藏标注及编辑控件不进入图片。图层图片通过允许跨域使用的 Image 加载后绘入 Canvas；遇到跨域拒绝或网络失败会尝试备用源并明确提示，导出过程中可以取消。PNG 是预览视窗的分享图片，编辑文件保留全部标注及完整地图坐标。

原生图标归档版本：`afd8e14f043cec070122fc1f600ba3932f4dded3`。原文件仍保留在原哈希路径，玩家坦克的兼容版本另存于新哈希路径，来源与修正记录在 `data/map-editor-icons.json`。准备脚本为 `scripts/prepare-map-editor-icons.py`。战术符号保存在 `data/map-editor-symbols.json`，SVG 显示与 PNG 导出共用相同图形定义，编辑文件仅引用允许的标记 ID。它们随隐藏页面懒加载 JS 发布。

清空和导入确认弹窗按内容收缩、居中展示；内容过长时在弹窗内滚动，移动端也不继承研发计算器的整屏高度。

验证：`pnpm run check:map-editor` 覆盖编辑文件往返、恶意与异常输入拒绝、移动边界、箭头端点、撤销/重做与合并历史、草稿隔离及存储失败。此项已经加入 `pnpm run check`。交互与实际 PNG 效果按项目规则由浏览器验收。

本次按用户要求由用户在预览中进行交互和图片导出验收，未运行浏览器自动操作。

### 线条交互参考

参考成熟开源绘图项目已采用的方式，在现有地图编辑器中实现，不额外引入整套绘图库：

- [tldraw 线条创建](https://github.com/tldraw/tldraw/blob/main/packages/tldraw/src/lib/shapes/line/toolStates/Pointing.ts)：拖动创建线条，直接调整端点。
- [tldraw 线条控制点](https://github.com/tldraw/tldraw/blob/main/packages/tldraw/src/lib/shapes/line/LineShapeUtil.tsx)：拖动创建用控制点以添加新顶点。
- [Excalidraw 线条编辑](https://github.com/excalidraw/excalidraw/blob/master/packages/element/src/linearElementEditor.ts)：端点编辑与拖动线段中点增加拐点；使用拖动阈值，避免普通点击意外增加拐点。

已存在的走线文件及本地草稿保持版本 1；曲线和战术线使用可选字段扩展，区域增加 `shape` 类型。当前版本可以继续导入旧文件并修改端点与拐点；新增文件需要支持这些形状的版本打开。
