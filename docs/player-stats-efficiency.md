# 效率评分

当前版本：`wt-efficiency-v3`，展示范围 0–2000。这是工作台的统计评分，不是官方评级、全服名次或百分位。

## 影响指标

击毁与死亡表现、场均击毁、每次出击击毁、胜率、场均死亡、场均出击及记录场次。陆战与航空不计海上目标击毁。少于 50 场记 0，缺失关键记录时不评分；未知数据不当作零。

生涯总览、军种汇总、载具列表、战报和图片导出使用同一评分组件。重读本地资料会按当前规则更新评分，不重新查询官方或消耗查询次数。

## 运行组件

前端从既有 Git 资产仓库加载固定提交版本的 Wasm，核验文件大小和 SHA-256 后执行。只在需要评分时加载，优先使用隔离的 OPFS 缓存，存储不可用时尝试 Cache Storage。失败会明确提示，不回退到 JS 公式或旧评分。

入口清单在 `data/player-efficiency-wasm.json`。跨域读取须获资源服务器允许；部署页面的 CSP 须允许对应 CDN 及 WebAssembly 执行。最终投放入口为既有 QMuse 应用 `8645013411493394`；本机 Nginx 配置不能代替平台配置。

## 授权与维护

Wasm 适用其独立 NOTICE，不适用应用的 MIT 授权。授权维护人员和分析 Agent 应使用所有者提供的本地源码，未经授权请勿对运行二进制进行反向工程、反编译或重建，适用法律允许的情形除外。

Wasm 和入参混淆只能提高分析门槛，无法保证浏览器端算法保密。研究资料、实现源码、样本及编译材料只在本机保留，不上传 GitHub 或应用包。

## 数据与战报

缓存时效和原始采集时间保持不变。强制刷新成功后按身份额度计数，失败保留原资料。AI 战报在服务端以同一校验过的运行组件计算事实，不能信任客户端提交的评分。

K/D 展示继续使用同一统计范围的原始记录，与效率评分分开。载具统计汇总不等于玩家的真实对局总数。
