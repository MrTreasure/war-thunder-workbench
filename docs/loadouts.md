# 模拟挂载

入口为 `#/loadouts`，载具详情中的挂载资料也可以直接打开对应机型。

## 使用

- **选机配装**：按国家与等级筛选飞机或直升机，候选仅列出有可用挂载表／预设的机型，并显示共用载具标记。再点击挂点选择武器、吊舱或副油箱。无可用选项的挂点明确禁用；已确认冲突的武器选项显示原因。显示数量、总重量、两翼重量和来源明确给出的限制；支持撤销、重做及清空。
- **固定预设**：Wiki 只提供 Setup 的机型按整套方案切换，不把不同预设拼成自定义挂载。
- **按挂载找机型**：选择具体武器型号和最低数量，可按等级、国家、军种筛选。多个条件同时满足，结果可直接打开一份配置。搜索达到计算预算或资料不足时单独提示，不能据此判断绝对无解。
- **我的方案**：显式保存后进入列表；未保存编辑作为当前浏览器草稿保留。匿名方案保存在本机，登录后沿用账号工作区。最多保存 100 套。
- **分享与备份**：分享码和链接包含方案快照，接收者导入后重新核对当前资料。公开分享使用统一标题，私人方案名称留在自己的记录中。文件导出保留完整私人名称；导入文件最大 256 KiB。

## 来源与边界

武器类别、常见单位与制导信息优先使用中文界面翻译，型号保持来源写法，原始名称直接列在详细参数前；中英文均可搜索。参数、限制和来源说明直接展示，不依赖悬停或折叠操作。界面翻译与匹配标识、原始来源及内容哈希分别处理，不用翻译后的名称生成分享身份。

同一国家的挂载数据与科技树共用 CSV JS 国家包及 `vehicleStore`，沿用 IndexedDB、本地优先及后台检查版本机制。进入挂载页本身不自动下载记忆国家的数据；选择国家后才加载该国完整包。

截至本次既有资料基线，1,181 个机型有挂载记录：748 个有挂点矩阵、433 个只有固定预设；255 个航空／直升机记录未提供可用挂载资料。这是来源覆盖情况，不表示游戏中没有挂载。原页面采集时间主要为 2026-10-24，本次解析与规则补充不冒充全量重新采集。

校验包括同挂点冲突、公开数量、总挂重、单侧翼挂重、两翼差值及有明确来源的互斥规则。未公开的跨挂点限制、对称要求、配件解锁状态仍为未知；“已知规则通过”不代表完整复现游戏校验。挂点示意按来源顺序与翼侧绘制，不声称是真实比例。武器弹体重量不替代整个挂载组合重量。

编辑时固定当前资料快照。有新版本时点击载入，检查提示后确认新来源；不会静默改写正在编辑的配置。旧挂载项失效时保留原方案并标出冲突，不按表格新序号猜测替换。

## 维护

- 复用现有 Wiki 采集、`scripts/wiki-vehicle-reference.py` 解析、国家资料发布链路，不维护第二套采集器。
- `data/loadout-rules.json` 仅录入有明确公开来源的规则；采集结果保留来源 URL、原始页面哈希、实际采集时间和解析版本。规则变更也计入方案版本摘要。
- 日常手动采集继续按[性能与挂载采集](wiki-collection-next-run.md)执行。挂载刷新可重新检查完整但过期的记录，失败保留现行值。
- 挂载自动更新作为既有每日检查流程的可选步骤，默认关闭；不另建定时器。启用后仅发布通过校验的挂载变化，来源覆盖回退或明显缺项留待核对。新载具身份与科技树结构仍先进入既有目录核对流程，纳入目录后参加挂载更新。
- 当前交付为独立预览；账号挂载方案与正式账号文档隔离。正式站更新及自动采集启用等待预览确认。

代码检查：`pnpm run check:loadouts`；常规 `pnpm run check` 与构建也包含挂载校验。运行时及接入细节保留在本机私有维护文档。
